## Цель и рамки

Собираем одностраничный сайт кофейни на React + Tailwind + GSAP по [вайрфрейму v1](https://claude.ai/artifact/Xffrfw7CjtePSsZqqRcVAM): 12 блоков сверху вниз, у каждого своя анимация. Сначала вёрстка и анимации на заглушках, реальный контент — последним этапом.

Порядок блоков: 01 Шапка · 02 Hero · 03 Бегущая строка · 04 О нас · 05 Почему мы · 06 Хиты · 07 Меню · 08 От зерна до чашки · 09 Атмосфера · 10 Отзывы · 11 Контакты · 12 Футер.

- **Утверждено:** состав и порядок блоков, схема анимаций по каждому блоку, детальная анимация блока 08 (есть живое демо в вайрфрейме).
- **Бренд:** кофейня — Willow We Love (coffee shop & bistro, Белград). Палитра утверждена: с их меню и афиши — см. токены в `src/index.css` и раздел «Решения по ходу».
- **Не утверждено:** логотип и шрифты, тексты, фото, адрес, языки сайта — см. «Открытые вопросы».
- **Правки по ходу:** фиксируем в этом документе, агент в редакторе всегда работает по его актуальной версии.

## Стек и установка

React + TypeScript на Vite, Tailwind v4, GSAP. Все плагины GSAP (SplitText, DrawSVG, ScrollSmoother и др.) с версии 3.13 бесплатны и лежат в обычном npm-пакете `gsap` — [GSAP 3.13](https://gsap.com/blog/3-13/).

| Что | Пакет | Зачем |
| --- | --- | --- |
| Сборка | `vite`, шаблон `react-ts` | dev-сервер, TypeScript из коробки |
| Стили | `tailwindcss` + `@tailwindcss/vite` | Tailwind v4, настройка через CSS ([установка с Vite](https://tailwindcss.com/docs/installation/using-vite)) |

- У секций `id` для якорей шапки: `about`, `menu`, `signature`, `gallery`, `contacts`.
- Анимации живут внутри компонента блока, в его `useGSAP` со `scope` на корень секции — селекторы не цепляют соседние блоки.
- Элементы для анимации помечаем `data-`атрибутами (`data-reveal`, `data-step-circle`), а не классами Tailwind: классы будут меняться, атрибуты — нет.

## Общие правила анимации

Всё, что не расписано отдельно, появляется одинаково: снизу на 40px с проявлением, 0.8s, `power3.out`, один раз — когда верх элемента доходит до 80% высоты экрана.

1. GSAP только внутри `useGSAP(() => {...}, { scope: ref })`, не в `useEffect`: хук сам откатывает твины и ScrollTrigger при размонтировании и в StrictMode.
2. Анимируем `transform`, `opacity` и `clip-path`. `width`, `top`, `margin` не трогаем — дёргается.
3. Адаптив через `gsap.matchMedia()`: на экранах < 768px нет pin и параллакса; при `prefers-reduced-motion: reduce` — только opacity, без движения.
4. SplitText запускаем после загрузки шрифтов (`document.fonts.ready` или `autoSplit` + `onSplit()`), иначе строки разобьются по запасному шрифту.
5. После загрузки картинок и шрифтов — `ScrollTrigger.refresh()`, иначе точки старта съедут.
6. Начальные состояния задаём в JS (`gsap.from`), а не классами `opacity-0` в разметке — без JS контент остаётся видимым.

Базовое появление — `src/hooks/useReveal.ts`, в разметке достаточно атрибута `data-reveal`:

```ts
import type { RefObject } from 'react'
import { gsap, useGSAP } from '../lib/gsap'

export function useReveal(scope: RefObject<HTMLElement | null>) {
  useGSAP(() => {
    const root = scope.current
    if (!root) return
    const mm = gsap.matchMedia()
    mm.add(
      { motion: '(prefers-reduced-motion: no-preference)', reduce: '(prefers-reduced-motion: reduce)' },
      (ctx) => {
        const { reduce } = ctx.conditions as { reduce: boolean }
        root.querySelectorAll<HTMLElement>('[data-reveal]').forEach((el) => {
          gsap.from(el, {
            y: reduce ? 0 : 40,
            opacity: 0,
            duration: reduce ? 0.4 : 0.8,
            scrollTrigger: { trigger: el, start: 'top 80%', once: true },
          })
        })
      },
    )
  }, { scope })
}
```

## Блок 08 «От зерна до чашки»

Один timeline на весь блок, ≈ 4.6s, запускается один раз, когда верх блока доходит до 65% экрана. Шаг длится 1.2s: цифра загорается, через 0.4s от неё тянется полоса (0.8s), в конце полосы загорается следующая цифра.

| Время | Что происходит |
| --- | --- |
| 0.0s | цифра 1 загорается, под ней текст 1 (flip) |
| 0.4–1.2s | полоса 1 → 2 |
| 1.2s | цифра 2 + текст 2 |
| 1.6–2.4s | полоса 2 → 3 |
| 2.4s | цифра 3 + текст 3 |
| 2.8–3.6s | полоса 3 → 4 |
| 3.6s | цифра 4 + текст 4, конец ≈ 4.6s |

- **Цифра:** внутри круга отдельный слой-заливка `opacity: 0 → 1` (со свечением через `box-shadow`), цифра `color → #fff`, круг `scale: 0.9 → 1`, `back.out(2)`, 0.5s. Слой проще и плавнее, чем твин цвета фона.
- **Текст, 3D Letter Flip:** SplitText по буквам, `rotationX: -100 → 0`, `opacity: 0 → 1`, `transformPerspective: 500`, `transformOrigin: '50% 100%'`, `stagger: 0.03`, 0.6s, `back.out(1.7)`, старт через 0.12s после цифры.
- **Полоса:** 3 сегмента между центрами кругов, `scaleX: 0 → 1` от левого края, 0.8s, `power2.inOut`; под ними серая пунктирная дорожка.
- **Reduced motion:** блок сразу в конечном состоянии — в разметке всё «горит», GSAP только ставит начальные состояния и анимирует.
- **Мобайл:** шаги вертикально, сегменты `scaleY` сверху вниз — отдельной задачей внутри этапа 3.

**Сделано (этап 3).** Актуальный код — `src/components/sections/Process.tsx`; набросок ниже оставлен как история. Чем реализация отличается от наброска:

- Полоса к следующему шагу лежит внутри своего `li`: на десктопе она шириной в колонку и растёт по `scaleX`, на мобайле — высотой «шаг + зазор» и растёт по `scaleY`. Один элемент на оба варианта.
- Анимация собрана на `from()`: конечные значения берутся из разметки, цвета — из токенов, в JS нет ни одного цвета.
- SplitText режет на слова и буквы (`words,chars`), чтобы слово не рвалось при переносе. После проигрыша текст возвращается в обычный вид, инлайновые стили снимаются.
- Цепочка играет строго один раз: смена языка или ширины экрана после старта её не перезапускает. До старта смена языка пересобирает разбивку под новый текст; у `h3` стоит `key={lang}`, иначе React и SplitText правили бы один и тот же узел.
- При reduced motion GSAP не трогает блок вообще — он сразу в конечном состоянии.

Набросок для старта (desktop). Он написан до мультиязычности: теперь названия шагов лежат в локалях (`t.process.steps`), а `useGSAP` должен пересобираться при смене языка (`dependencies: [lang], revertOnUpdate: true`), иначе SplitText останется на старом тексте. Исходный вариант — `src/data/steps.ts`:

```ts
export const steps = [
  { n: 1, title: 'Зерно' },
  { n: 2, title: 'Обжарка' },
  { n: 3, title: 'Заваривание' },
  { n: 4, title: 'Чашка' },
]
```

`src/components/sections/Process.tsx`:

```tsx
import { useRef } from 'react'
import { gsap, SplitText, useGSAP } from '@/lib/gsap'
import { steps } from '@/data/steps'

export function Process() {
  const root = useRef<HTMLElement>(null)

  useGSAP(() => {
    const el = root.current
    if (!el) return
    const mm = gsap.matchMedia()

    mm.add('(min-width: 768px) and (prefers-reduced-motion: no-preference)', () => {
      const circles = el.querySelectorAll<HTMLElement>('[data-step-circle]')
      const fills = el.querySelectorAll<HTMLElement>('[data-step-fill]')
      const nums = el.querySelectorAll<HTMLElement>('[data-step-num]')
      const segs = el.querySelectorAll<HTMLElement>('[data-step-seg]')
      const splits = Array.from(el.querySelectorAll<HTMLElement>('[data-step-title]')).map((t) =>
        SplitText.create(t, { type: 'chars' }),
      )

      // начальные состояния
      gsap.set(fills, { opacity: 0 })
      gsap.set(nums, { color: '#8C8276' })
      gsap.set(circles, { scale: 0.9 })
      gsap.set(segs, { scaleX: 0, transformOrigin: 'left center' })
      splits.forEach((s) =>
        gsap.set(s.chars, { rotationX: -100, opacity: 0, transformPerspective: 500, transformOrigin: '50% 100%' }),
      )

      const tl = gsap.timeline({ scrollTrigger: { trigger: el, start: 'top 65%', once: true } })

      steps.forEach((_, i) => {
        const at = i * 1.2
        tl.to(fills[i], { opacity: 1, duration: 0.5, ease: 'power1.out' }, at)
          .to(nums[i], { color: '#ffffff', duration: 0.5 }, at)
          .to(circles[i], { scale: 1, duration: 0.5, ease: 'back.out(2)' }, at)
          .to(splits[i].chars, { rotationX: 0, opacity: 1, duration: 0.6, ease: 'back.out(1.7)', stagger: 0.03 }, at + 0.12)
        if (segs[i]) tl.to(segs[i], { scaleX: 1, duration: 0.8, ease: 'power2.inOut' }, at + 0.4)
      })

      return () => splits.forEach((s) => s.revert())
    })
  }, { scope: root })

  return (
    <section ref={root} id="process" className="py-24">
      <div className="mx-auto max-w-[1120px] px-4">
        <h2 data-reveal className="text-4xl font-bold">От зерна до чашки</h2>
        <ol className="relative mt-16 grid gap-10 md:grid-cols-4 md:gap-0">
          <div aria-hidden className="absolute inset-x-[12.5%] top-[35px] hidden border-t-2 border-dashed border-ink/20 md:block" />
          {steps.slice(0, -1).map((s, i) => (
            <div
              key={s.n}
              data-step-seg
              aria-hidden
              className="absolute top-[34px] hidden h-1 w-1/4 rounded bg-accent md:block"
              style={{ left: `${12.5 + i * 25}%` }}
            />
          ))}
          {steps.map((s) => (
            <li key={s.n} className="relative flex flex-col items-center gap-6">
              <div data-step-circle className="relative grid size-[72px] place-items-center rounded-full border-2 border-ink/15 bg-paper">
                <span data-step-fill aria-hidden className="absolute -inset-0.5 rounded-full bg-accent shadow-[0_0_0_10px_rgb(1_90_46/0.14)]" />
                <span data-step-num className="relative text-2xl font-bold text-white">{s.n}</span>
              </div>
              <h3 data-step-title className="text-2xl font-semibold">{s.title}</h3>
            </li>
          ))}
        </ol>
      </div>
    </section>
  )
}
```

`md:gap-0` у сетки важен: колонки ровно по 25%, поэтому центры кругов на 12.5 / 37.5 / 62.5 / 87.5%, и сегменты по 25% попадают точно между ними.

## Как вести проект с агентом

Одна задача агенту — один этап или один блок; после неё проверка в браузере и коммит.

1. Экспортируй этот документ в Markdown и положи в корень репозитория как `PLAN.md`. В файл правил, который читает твой агент (например, `CLAUDE.md` или `AGENTS.md`), добавь строку: «План и спецификация — в PLAN.md, читай его перед каждой задачей».
2. Не проси «сделай весь сайт» — вёрстку одним куском потом дольше чинить, чем собрать по блокам.
3. К задаче на вёрстку блока прикладывай его скриншот из вайрфрейма — агенту проще попасть в раскладку.
4. После задачи: смотришь на 375 и 1440px, коммит. Правки анимаций сразу вносишь в `PLAN.md`, чтобы следующая сессия работала по актуальной версии.
5. Правила, которые стоит держать в файле правил агента: GSAP только из `@/lib/gsap` и только в `useGSAP`; анимируемые элементы — через `data-`атрибуты; на этапе вёрстки без анимаций; новые библиотеки — только с согласия.

  Что сделано:
  - Одноразовые появления больше не на ScrollTrigger, а на IntersectionObserver — `lib/inView.ts` (`onceInView`, `batchInView`, `watchInView`). Было около 75 ScrollTrigger'ов, каждый при создании и при каждом пересчёте заставлял браузер заново раскладывать страницу; осталось 5 — там, где нужны scrub, pin или скорость скролла. **Правило на будущее: одноразовый показ — через `lib/inView`, ScrollTrigger — только для scrub и pin.**
  - Особенность IntersectionObserver: если блок перепрыгнули (якорь, быстрый бросок), его анимация сыграет, когда до него докрутят обратно, а не «за кадром».
  - Шапка прячется и возвращается обычным слушателем скролла, без ScrollTrigger.
  - Параллаксы (hero, «О нас», галерея), бегущая строка и карусель отзывов настраиваются после показа первого экрана — `hooks/useAfterIntro.ts`. Закрепление «Хитов» не откладывается: оно меняет высоту страницы, и при обновлении страницы с середины она съехала бы.
  - В «О нас» и галерее по одному таймлайну на блок вместо ScrollTrigger на каждый элемент; сдвиг фото в «Хитах» идёт в общем таймлайне, без `containerAnimation`.
  - Шрифты лежат в проекте: `src/assets/fonts` + `src/fonts.css`, латинские части подгружаются заранее (`preload` в `index.html`). Стартовая анимация ждёт только те части шрифта, которые нужны тексту на экране. Запросов к Google Fonts больше нет.
  - Код карусели отзывов вместе с Draggable и InertiaPlugin вынесен в отдельный файл и подгружается после первого экрана (`lib/horizontalLoop.ts` регистрирует эти плагины сам).
  - Заголовок hero возвращается в обычный текст сразу, как доехал, — это раньше отмечает LCP.
  - Лишние пересчёты ScrollTrigger на старте убраны (при первом показе язык и вкладка меню не «меняются»).
  - Доступность: ссылка «Перейти к содержанию», стрелки / Home / End по вкладкам меню, имя кнопок языка включает видимую надпись, контраст подписей на заглушках. Добавлен `public/robots.txt`.

  Почему на мобайле не 90. Lighthouse меряет на медленном 4G с замедленным процессором. Страница рисуется только после загрузки JavaScript (150 КБ в сжатом виде), а первый экран по задумке появляется анимацией: заголовок доезжает через секунду после старта. Поэтому FCP не опускается ниже ≈ 2.3 с, а LCP — ниже ≈ 3.3 с; для оценки 90 нужны 1.8 с и 2.5 с. Варианты:
